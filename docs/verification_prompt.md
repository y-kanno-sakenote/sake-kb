# 裏取り依頼の型（sake-kb で事実を検証させるときのプロンプト規格）

2026-09-05 制定。背景: 清酒無双の定数裏取りで、実装側（Opus）が2回「出典の逆接の後半を落として一般化」し（麹蓋「品質が上がる」／五百万石「不向き」→「不可」）、検証係の引き直しで降格した。集計も判定表と食い違った。以下を委任文に**そのまま貼る**。

## 依頼文に必ず入れる5条
1. **原文引用**: 判定行ごとに、根拠にした KB の原文を**15字以上そのまま**引用する（`kb.py --full` の該当行）。要約・言い換えだけの行は「根拠なし」扱いにする。
2. **逆接・限定の保持**: 原文に「が」「ただし」「〜とされる」「〜も知られている」「不向き」があれば、その語を引用に含め、判定を一段弱める（矛盾→部分、裏取れた→部分）。「不向き」は「不可」ではない。
3. **矛盾の条件**: 「矛盾」は KB の事実と**逆**のときだけ。KB に無い・別軸の事実しか無いは「根拠なし」。
4. **集計は機械で**: 判定表を書き終えてから、判定列を数えて集計表を作る（手で先に書かない）。件数が合わない表は差し戻し。
5. **出典表記**: ADR-018 の形式（教科書「書名 / 部 / p.N」、論文「誌名 巻(号) 年 p.N」、百科「書名 p.N」、DB「NRIB 実もろみDB 仕込番号N（取得日）」）。台帳にない資料と Web 検索は使わない。

## 依頼の流れ（本体の作法）
- 実装・調査側（Opus/Sonnet）が検証表 → **qa係が抜き取り**（矛盾は全件、裏取れたは無作為4〜8件、根拠なしは言い換え再検索）→ 本体が訂正 → 反映はオーナー判断。
- 委任文には分量上限（例「20行以内」）と「ファイルは編集しない／DB 読み取り専用／commit しない」を書く。
- 検証表の置き場: そのプロジェクトの `docs/<対象>_verification.md`（かもしてぽん・清酒無双の前例）。

## 貼り付け用（短縮版）
```
裏取り規格（sake-kb/docs/verification_prompt.md）: ①判定行ごとにKB原文を15字以上そのまま引用（要約だけの行は根拠なし扱い）②原文の逆接・限定（が／ただし／とされる／不向き）は引用に含め判定を一段弱める③「矛盾」はKBの事実と逆のときだけ、無い・別軸は「根拠なし」④集計は判定表を書き終えてから判定列を数えて作る⑤出典はADR-018形式、台帳外の資料とWeb検索は不可。
```
